## Guardrails and stop conditions

- Default to one implementation owner followed by one checker; no external provider/channel without explicit user approval.
- The final user test is one checkpoint after automation, not repeated manual micro-validation.
- Focused gates while fixing; one broad gate before review and one after concrete review fixes.
- At four active hours, report progress/risk. At eight hours, stop for explicit approval.
- A harness-only flake gets two distinct fixes or 90 minutes, then is simplified/deferred with its exact owner.
- Do not add self-hosted/public Relay workflows, state/socket CLI overrides, extra daemon-like harnesses, automatic rollback drills, or unsupported-platform runtime code unless a named acceptance failure requires them.

## Rollback points

- Hosted installed-artifact evidence precedes namespace/network changes.
- Namespace orchestration remains tests-only and cannot change public zterm behavior.
- A failed immutable candidate is never edited; corrections use a new version/tag.
- Parent/task completion remains reversible until the user final acceptance record is attached.
