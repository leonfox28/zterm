# 优化 Zterm CLI 命令与执行方式

## Goal

让 Zterm CLI 面向人的日常操作：统一输出和确认方式，简化初始化与配对，更新后自动启动 daemon，并补齐现有日志的关键事件以支持开发排障。

## Background and Confirmed Facts

以下源码位置记录实现前的基线证据；最终行为与验证见需求验收及 `research/validation.md`。

- 用户明确要求创建 Trellis 任务，并要求本轮先盘点现有指令及用途。
- 当前源码版本为 `0.1.18`（`Cargo.toml:14`）；命令树有 12 个公开顶层入口，展开为 21 个具体操作，另有裸调用、帮助/版本选项以及 4 个隐藏内部入口（`crates/cli/src/lib.rs:28`、`:133`）。
- 当前命令、参数、默认值、daemon 启动行为和源码证据已记录在 `research/current-cli.md`。
- 用户在频繁开发更新中遇到 `update` 因存活会话报错、要求重新添加 `--force`，以及更新后 daemon 保持停止的问题。
- 当前 `--json` 用于 `status`、`doctor`、`daemon status`、`device list`、`session list`（`crates/cli/src/lib.rs:217`、`:305`）；安装/更新器另行依赖隐藏 self-check JSON（`crates/daemon/src/distribution.rs:499`）。
- 当前 update 在验证下载候选后检查会话并强制要求 `--force`，激活后不启动 daemon（`crates/daemon/src/operations.rs:390`）；stop/restart 也以 force 为门槛（`:1010`、`:1031`）。daemon 已提供存活会话名称（`crates/daemon/src/service.rs:88`）。
- 底层 `LocalStopRequest` 当前忽略其 force 字段、直接开始 shutdown（`crates/daemon/src/service.rs:892`）；只在 CLI 观察会话数量不足以保证检查与停止之间新建的会话不会被未经确认地结束。
- 用户选择 C1–C6 后进一步明确移除 `logs -f`，以减少额外维护；其余优化保留，C6 收窄为 `-n` 简写和现有尾部查看。检查发现项目自己的 13 处 tracing 均在 lifecycle/local_ipc；日志覆盖缺口及文件轮转事实见 `research/logging-gap-analysis.md`。

## Requirements

- R1：完整盘点当前公开命令、子命令、主要参数和实际用途，单独说明隐藏内部入口。
- R2：解释裸调用、初始化、按需启动 daemon、会话创建/连接/脱离/结束和方向性配对的执行语义。
- R3：公开命令统一保留人类可读文本输出，删除五处 `--json` 参数及对应公开 JSON 渲染路径；帮助、文档和相关验证随之更新。不得为了保留公开 JSON 的旧测试而保留该产品功能。
- R4：`update`、`daemon stop`、`daemon restart` 在 daemon 未运行或没有存活会话时，直接执行各自操作，不额外询问会话中断确认。
- R5：上述三个命令默认只要会影响存活会话，就先用英文列出当前会话名称，说明所有运行中会话将被结束，并让用户输入 `y` 继续；确认后在同一次命令调用内完成操作，不再要求用户重新输入命令。
- R6：确认依据是存活会话，而非是否有客户端连接。无人连接但后台仍运行的会话需要确认；仅有连接但没有存活会话不触发该确认。
- R7：更新成功后启动新版本 daemon，不再以 daemon 保持停止作为成功结果。已初始化但更新前 daemon 未运行的情况同样需要启动；启动失败必须明确报告，不能输出完整成功。
- R8：确认输入接受 `y` 或 `yes`，忽略首尾空白和大小写；`n`、空行、EOF 及其他输入均取消，不得因此停止 daemon、结束会话或激活新版。
- R9：上述三个命令提供 `-y`（与已有命令风格一致，同时提供长名 `--yes`）显式跳过会话中断确认并直接执行；移除其 `--force`，不保留隐藏兼容别名。非交互输入在存在会话且未提供 `-y`/`--yes` 时取消，给出英文使用提示；零会话仍直接执行。
- R10：判断没有会话之后，如停止请求实际遇到新建会话，不能未经确认结束它们。默认交互回到当前调用内的名称展示与确认；`-y` 则已明确允许中断。
- R11：这轮新增或修改的帮助、确认、取消及执行结果文案均为英文；任务讨论和规划文档可继续使用中文。
- R12（C1）：`session close`、`device revoke`、`reset --identity`、`uninstall` 也统一使用 R8 的确认输入和 `-y/--yes`。reset/uninstall 移除公开 `--force`，将结束会话和删除身份/程序的影响合并成一次确认。存在实际删除影响时，即使零会话也要确认；已无状态可重置时维持无副作用成功。
- R13（C2）：设备与会话列表采用名称优先的清晰英文表格，完整 ID 仍可取得，设备控制权限两个方向可分辨，会话显示 attached/detached。空列表明确说明并提供下一步命令；不得将未连接推断为远端不可达。
- R14（C2）：`status` 优先展示设备名、版本、daemon 状态、基础设施、网络概况和会话名称/数量；底层连接、地址发布/查找等诊断细节移入 `doctor` 的人类可读结果，保持其观察操作不启动 daemon。
- R15（C3）：首次 setup 的基础设施默认为 official-n0，不再询问 profile，也不要求非交互调用显式传 --profile；显式 self-hosted 仍支持 relay 参数/交互。设备名仍可交互输入或通过 --name 提供；重复 setup 保留既有身份和配置，不能暗中变成改名或切换基础设施。
- R16（C4）：`pair accept --name` 改为 `--alias`，成功后用英文说明所获得的控制方向，并输出使用真实已选别名的 connect 指引；pair create 给出有效期和接收端操作说明，票据正文仍只在 stdout 输出一次，指引使用 stderr。修正 --ttl 帮助中不合法的 30s 示例。
- R17（C5）：`zterm session list` 省略目标时默认 local；显式远端/本地目标保持可用，其他多位置参数命令不改目标解释规则。
- R18（收窄后的 C6）：`logs` 保留一次性有界尾部查看，增加 `-n` 作为 `--lines` 简写；缺少日志时给出英文说明。查看操作不创建状态或启动 daemon。本轮不提供 `-f/--follow`，不引入文件监听、持续读取或跨轮转跟随逻辑。
- R19（现有日志完善）：默认日志补齐 daemon 版本/启停、Session 创建/结束/退出原因、控制端连接/脱离/接管、网络异常与恢复、主连接建立/关闭、配对和授权操作结果。日志使用英文文本，包含时间、级别、模块、必要的关联信息和稳定错误原因；正常操作与异常清晰区分。
- R20（现有日志完善）：只记录关键事件和状态变化，避免逐帧、逐按键、逐 RTT 或重复状态刷屏；保留终端内容、票据、密钥等已有内容边界。更新过程的下载/验证/停止/激活/启动阶段在调用 CLI 中可见，daemon 日志记录其自身启停与新版本就绪，不能把更新失败统称为启动失败。

## Scope and Existing Boundaries

- 本轮 JSON 移除针对公开 CLI 输出。隐藏安装器自检、签名清单、持久化配置及内部 IPC 序列化属于内部实现，继续按其已有消费者契约工作。
- 会话不会因新版 daemon 启动而恢复；确认文案需要明确此操作会结束列出的会话。
- 下载/签名/构建身份校验仍须在停止 daemon 和替换程序前完成；保留已有激活失败回滚边界。
- 尚未 setup 的安装仍可更新程序，但更新后输出英文 `Run zterm setup to configure and start the daemon.`，不得擅自创建新身份或选定设备配置。自动启动成功要求适用于已初始化设备。
- 日志继续使用现有 tracing、daemon.log / daemon.log.1 及启动前 4 MiB 轮转规则；不将其描述为运行时硬容量限制。日志完善聚焦诊断事件，保留现有写入和尾部读取边界，不引入新的日志服务、持续轮转引擎或多进程写入者。

- [x] R4：daemon 停止或运行但零会话时，三个命令不提示会话确认；stop 完成停止/已停止处理，已初始化设备的 restart 最终启动 daemon、update 完成升级后启动 daemon。
- [x] R5/R6：存在已连接或已脱离客户端的会话时，列出名称；输入 `y` 后直接完成所请求的操作，无需重跑命令。

- [x] R7：更新后的 daemon 来自已激活的新程序，成功输出与真实启动结果一致；启动失败可见且不误报更新全部成功。
- [x] R9：三个命令的 `-y`/`--yes` 均不读取确认输入，旧 `--force` 被参数解析拒绝；非交互且有会话时必须显式提供新参数。
- [x] R10：确定性模拟“观察到空闲后、停止前新建会话”，未确认的停止保持会话和 daemon 存活，并在同一调用内返回确认流程。
- [x] R11：公开提示为英文，包含会话名称、结束影响和 `[y/N]`；相应帮助、文档、规范及回归验证均更新。
- [x] R7：未初始化设备更新后获得 setup 指引且不产生新身份；新程序已安装但 daemon 启动失败时返回明确的部分完成错误。
- [x] R12：四个新增命令接受 y/yes 和 -y/--yes；reset/uninstall 在有会话时一次确认即可执行，零会话但有删除影响仍需确认；公开 --force 全部消失。
- [x] R13/R14：列表可读且不丢失设备身份/方向权限，空结果有指引；status 展示可用版本与会话名称，doctor 保留诊断信息；这些观察操作保持既定不启动/按需启动语义。
- [x] R15：首次 `setup --name <name>` 不再要求 --profile；默认交互不询问 profile，自建 Relay 路径和重复 setup 身份稳定性验证通过。
- [x] R16：--alias 可用，旧 pair accept --name 不再出现在帮助且被解析拒绝；成功指引使用实际别名；票据只输出一次且日志无票据；TTL 帮助示例均可通过现有验证。
- [x] R17：省略目标与显式 local 的 session list 结果一致，显式远端解析保持原契约。
- [x] R18：`logs -n N` 与 `logs --lines N` 等价；原行数/字节上限及不启动 daemon 的验证通过，缺少日志有英文说明；帮助不宣传 `-f/--follow`，实现中没有持续读取者。
- [x] R19/R20：确定性会话生命周期与网络退化/恢复产生可关联英文事件和原因，正常脱离/未变化状态不刷告警；哨兵终端正文、票据和 cwd 不出现在捕获日志中；更新阶段显示与实际执行顺序一致。

## Out of Scope

- 不更改远端协议、配对方向、终端渲染或会话持久化能力。
- 不为更新后恢复已经结束的会话新增机制。
- 除 pair accept 的 --alias 参数调整外，不合并或重命名现有命令，不引入交互式设备/会话选择器、远端 exec、配置编辑或安装器序列化重构。
- 不新增远程日志上传、终端录制、全量请求跟踪或动态日志过滤配置。
- 不实现 `logs -f/--follow` 或额外日志记录系统。
